## 什么是 Web 安全

Web 安全就是保护网站和 Web 应用不被黑客攻击、篡改、窃取数据。随着互联网的发展，Web 应用越来越复杂，安全问题也越来越多。

## 1. 注入漏洞（Injection）

注入是最常见的漏洞之一，黑客把恶意代码注入到应用中，让服务器执行。

### SQL 注入

**原理**：用户输入的数据被拼接到 SQL 语句中，没有经过过滤，导致黑客可以篡改 SQL 逻辑。

**例子**：
```sql
-- 正常的登录验证
SELECT * FROM users WHERE username = 'admin' AND password = '123456'

-- 黑客在密码框输入 ' OR '1'='1
SELECT * FROM users WHERE username = 'admin' AND password = '' OR '1'='1'
-- 结果永远为真，直接登录成功
```

**常见类型**：
- 联合查询注入（UNION）
- 报错注入
- 布尔盲注
- 时间盲注
- 堆叠查询注入

**防御方法**：
- 使用参数化查询（预编译语句）
- 输入验证和过滤
- 最小权限原则（数据库用户权限不要太大）

### 命令注入

**原理**：应用把用户输入直接传给系统命令执行函数，黑客可以执行任意系统命令。

**例子**：
```python
# 应用代码
import os
ip = request.args.get('ip')
os.system(f"ping -c 1 {ip}")

# 黑客输入 127.0.0.1; whoami
# 实际执行：ping -c 1 127.0.0.1; whoami
# 结果：执行完 ping 后，还执行了 whoami 命令
```

**防御方法**：
- 避免使用系统命令执行函数
- 如果必须用，严格过滤特殊字符（; | & ` $ 等）
- 使用白名单验证

## 2. 失效的身份认证（Broken Authentication）

身份认证机制设计有缺陷，黑客可以冒充其他用户。

**常见问题**：
- 密码明文存储
- 登录没有次数限制（可以暴力破解）
- Session 管理不安全
- 弱密码策略
- 找回密码功能有漏洞

**防御方法**：
- 密码加密存储（bcrypt、Argon2）
- 登录失败次数限制
- 使用强 Session 管理
- 双因素认证（2FA）

---

## 3. 敏感数据泄露（Sensitive Data Exposure）

敏感数据没有加密保护，被黑客窃取。

**常见问题**：
- 密码明文存储在数据库
- 信用卡号、身份证号明文传输
- 网站没有 HTTPS
- 错误信息泄露服务器路径、数据库结构

**防御方法**：
- 敏感数据加密存储
- 全站 HTTPS
- 错误信息统一处理，不泄露敏感信息
- 敏感字段脱敏显示

---

## 4. XML 外部实体（XXE）

XML 解析器配置不当，黑客可以通过 XML 文档读取服务器文件、发起攻击。

**原理**：XML 支持外部实体引用，黑客可以构造恶意 XML，让服务器读取本地文件。

**例子**：
```xml
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<foo>&xxe;</foo>
```

**防御方法**：
- 禁用 XML 外部实体
- 使用 JSON 代替 XML
- 更新 XML 解析器到最新版本

---

## 5. 失效的访问控制（Broken Access Control）

权限控制有缺陷，普通用户可以访问管理员功能。

**常见类型**：
- **水平越权**：普通用户 A 可以查看普通用户 B 的数据
- **垂直越权**：普通用户可以访问管理员功能
- 直接访问 URL：直接输入管理员页面地址就能访问

**例子**：
```
# 普通用户直接访问管理员页面
https://example.com/admin/delete-user?id=1
# 没有验证权限，直接删除了用户
```

**防御方法**：
- 每个页面都做权限验证
- 使用访问控制列表（ACL）
- 默认拒绝，明确授权

---

## 6. 安全配置错误（Security Misconfiguration）

服务器、数据库、应用配置不安全。

**常见问题**：
- 默认密码没有改
- 目录列表开启
- 详细错误信息显示给用户
- 不必要的端口和服务开启
- 管理后台暴露在公网

**防御方法**：
- 修改默认密码
- 关闭目录列表
- 统一错误页面
- 最小化安装，只开必要服务

---

## 7. 跨站脚本（XSS）

黑客把恶意脚本注入到网页中，其他用户访问时执行脚本。

**类型**：
- **反射型 XSS**：恶意脚本在 URL 里，服务器直接反射给用户
- **存储型 XSS**：恶意脚本存在数据库里，所有访问的用户都会中招
- **DOM 型 XSS**：前端 JavaScript 处理不当导致的

**例子**：
```javascript
// 黑客在评论区输入
<script>alert('偷你Cookie: '+document.cookie)</script>

// 其他用户访问页面时，脚本执行，Cookie 被发送给黑客
```

**防御方法**：
- 输出编码（HTML 转义）
- CSP（内容安全策略）
- HttpOnly Cookie
- 输入验证

---

## 8. 不安全的反序列化（Insecure Deserialization）

反序列化不可信的数据，导致远程代码执行。

**原理**：应用把用户提交的序列化数据直接反序列化，黑客可以构造恶意序列化数据，执行任意代码。

**常见场景**：
- Java 反序列化漏洞
- PHP 反序列化漏洞
- Python pickle 反序列化

**防御方法**：
- 不要反序列化不可信的数据
- 使用白名单验证反序列化的类
- 签名验证

---

## 9. 使用含有已知漏洞的组件（Vulnerable Components）

使用的第三方库、框架有已知漏洞。

**例子**：
- 用了有漏洞的 Log4j
- 用了有漏洞的 Spring Framework
- 用了有漏洞的 jQuery 版本

**防御方法**：
- 定期更新依赖
- 使用 SCA（软件成分分析）工具扫描
- 不用的组件及时删除

---

## 10. 不足的日志记录和监控（Insufficient Logging）

没有记录足够的安全事件，被攻击了都不知道。

**问题**：
- 登录失败没有记录
- 敏感操作没有日志
- 日志没有监控，被攻击了没人发现

**防御方法**：
- 记录所有安全相关事件
- 日志集中管理
- 设置告警机制
- 定期审计日志

## 其他常见漏洞

### CSRF（跨站请求伪造）

**原理**：黑客诱导已登录用户点击恶意链接，以用户的身份执行操作。

**例子**：
```html
<!-- 黑客网站上的图片 -->
<img src="https://bank.com/transfer?to=hacker&amount=10000">

<!-- 用户已登录银行账号，访问黑客网站时，图片加载就发起了转账请求 -->
```

**防御方法**：
- CSRF Token
- 验证 Referer
- SameSite Cookie

### 文件上传漏洞

**原理**：应用没有验证上传的文件类型，黑客上传 Webshell，控制服务器。

**例子**：
```php
// 黑客上传 shell.php
<?php eval($_POST['cmd']); ?>

// 然后访问上传的文件，执行任意命令
```

**防御方法**：
- 白名单验证文件类型
- 重命名上传的文件
- 上传目录禁止执行脚本
- 文件内容检查

### SSRF（服务端请求伪造）

**原理**：黑客让服务器发起请求，访问内部服务或敏感资源。

**例子**：
```
# 应用提供截图功能，用户输入 URL
https://example.com/screenshot?url=http://internal-admin/

# 服务器去访问内部管理后台，把结果返回给黑客
```

**防御方法**：
- 白名单验证请求的域名
- 禁止访问内网地址
- 限制请求协议（只允许 HTTP/HTTPS）

### 文件包含漏洞

**原理**：应用包含用户指定的文件，黑客可以包含恶意文件。

**类型**：
- 本地文件包含（LFI）
- 远程文件包含（RFI）

**防御方法**：
- 白名单验证包含的文件
- 关闭远程文件包含

## 渗透测试流程

作为安全学习者，我了解的渗透测试基本流程：

1. **信息收集**：收集目标网站的信息（子域名、端口、技术栈）
2. **漏洞扫描**：用工具扫描常见漏洞
3. **手动测试**：手动验证漏洞，确认可利用性
4. **权限提升**：拿到权限后提升到更高权限
5. **痕迹清理**：清除操作日志
6. **报告编写**：整理发现的漏洞，写修复建议

## 工具推荐

- **Burp Suite**：抓包改包，最常用的 Web 安全工具
- **Nmap**：端口扫描
- **SQLmap**：SQL 注入自动化工具
- **Xray**：漏洞扫描
- **Kali Linux**：渗透测试专用系统

## 结语

Web 安全是一场没有终点的攻防战。作为学习者，我们不仅要知道怎么攻击，更要知道怎么防御。知己知彼，才能保护好自己的系统。

安全不是产品，是过程。
